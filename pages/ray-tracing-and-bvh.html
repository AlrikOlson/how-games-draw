Ray Tracing & the BVH

Ray tracing draws a picture by asking one question for every pixel on the screen: what is the first thing in this direction. That imaginary line is a ray. Checking it against every wall, crate and leaf in a scene would take far too long, so the scene is wrapped in a tree of boxes inside boxes, and a ray only opens the boxes it actually touches. A few dozen box checks replace millions of edge checks. The thing people get wrong: the ray tracing hardware in a graphics card only walks that tree. Building the tree, and keeping it current as things move and bend, is still work your game pays for every frame.

A ray that misses a box never looks inside it, so the work grows with the depth of the tree, not the size of the village.

Under the hood: the math and the code

A ray is a start point o plus a direction d, and every point on it is o + t·d, where t is the distance travelled. The closest hit is the smallest positive t over every surface. Brute force computes t for all N segments, so cost grows in step with N.

The BVH is a tree of axis-aligned boxes, meaning boxes whose sides line up with the x and y axes. Each interior node stores the box around both of its children; each leaf stores a few segments. Testing a ray against a box is the slab test, which treats each pair of opposite walls as a slab and asks where the ray is between them.

In words: for each axis, find where the ray enters and leaves the two walls; keep the latest entry and the earliest exit. The ray hits the box if entry comes before exit.

slab test, per axis a: t0 = (bmin_a − o_a) / d_a, t1 = (bmax_a − o_a) / d_a t_near = max over a of min(t0, t1), t_far = min over a of max(t0, t1) hit ⇔ t_near ≤ t_far and t_far ≥ 0 and t_near ≤ t_max expected nodes visited per ray ≈ O(log N) (SAH-built tree, ~1.5–2 × log₂ N in practice)

bmin and bmax are the two corners of the box, o and d are the ray, t_near and t_far are where the ray enters and leaves, and t_max is the closest hit found so far. A tree built with the SAH, the split rule from the next section, visits about 1.5 to 2 times log₂ N boxes per ray, so a scene ten times bigger costs only a few more box tests.

What this code does: runs the slab test with one multiply per wall, because 1/d was computed once per ray, and returns whether the ray passes through the box.

bool slab(vec3 bmin, vec3 bmax, vec3 o, vec3 invD, float tMax, out float tNear) {
  vec3 t0 = (bmin - o) * invD;   // invD = 1/d, computed once per ray: no divides here
  vec3 t1 = (bmax - o) * invD;
  vec3 tmin = min(t0, t1), tmax = max(t0, t1);
  tNear = max(max(tmin.x, tmin.y), max(tmin.z, 0.0));
  float tFar = min(min(tmax.x, tmax.y), min(tmax.z, tMax));
  return tNear <= tFar;      // 6 mul, 6 min/max, 1 compare per box
}

Cut where the gaps are, not down the middle: you pay once when the tree is built and save on every ray after.

Under the hood: the math and the code

Two choices define a build: where to split a node, and when to stop and make a leaf. Median split sorts the segments by their centre point along the box's longest axis and halves the list. The tree is balanced, but it ignores where the geometry is, so sibling boxes overlap and a ray often has to enter both.

The surface area heuristic (SAH) prices each candidate split by how likely a random ray is to enter each child, times the work waiting inside it. That likelihood is proportional to the child's surface area, which in this 2D demo is its perimeter. Production builders do not try every position. They sort segments into 12 to 32 bins per axis and only try the bin edges.

In words: a split costs one box test, plus each child's share of the rays times the number of segments inside it.

C(split) = C_t + (A_L / A) · N_L · C_i + (A_R / A) · N_R · C_i C_t cost of one box test A area of this node C_i cost of one primitive test A_L, A_R child areas leaf if C(best split) ≥ N · C_i, or N ≤ leaf size

C_t is the cost of one box test and C_i the cost of one segment test. A is the area of the node being split, A_L and A_R the areas of the two children, and N_L and N_R the segment counts in each. If the best split costs more than testing all N segments directly, stop and make a leaf.

What this code does: drops each segment into one of 12 bins along an axis, then sweeps the bin edges from both ends so each candidate cut costs 12 steps instead of one per segment.

// binned SAH split for prims[s..e), NB = 12 bins per axis
best.cost = INF;
for axis in {x, y, z} {
  for p in prims[s..e) {
    k = clamp((centroid(p)[axis] - cmin) / (cmax - cmin) * NB, 0, NB - 1);
    bins[k].count++;  bins[k].box |= bounds(p);
  }
  // suffix sweep right-to-left, then prefix left-to-right: each candidate costs O(NB), not O(N)
  for k = NB-1 .. 1  { R[k] = R[k+1] | bins[k].box;  nR[k] = nR[k+1] + bins[k].count; }
  L = empty; nL = 0;
  for k = 0 .. NB-2 {
    L |= bins[k].box;  nL += bins[k].count;
    cost = C_t + (area(L) * nL + area(R[k+1]) * nR[k+1]) / area(node) * C_i;
    if (cost < best.cost) best = { cost, axis, plane: k + 1 };
  }
}
if (best.cost >= count * C_i) makeLeaf();      // splitting would cost more than testing everything
else { partition(prims, best); recurse(left); recurse(right); }

What the ray asks

Check the nearer half first, and every box that starts beyond the current hit costs nothing.

Under the hood: the math and the code

Traversal is a loop over a small stack of node indices. Pop a node, run the slab test on its box, and either discard it, test its segments if it is a leaf, or push both children. The near child goes on top so it is popped first; near is decided by the sign of the ray direction along the node's split axis, the axis the box was cut along. Finding a hit early shrinks t_max, the distance to the closest hit so far, and every box that starts beyond t_max is then rejected without being opened.

A shadow ray only needs to know whether anything at all is in the way, not what is closest. In any-hit mode the loop returns on the first segment hit, so it visits fewer nodes and never bothers ordering the rest. DXR, the DirectX ray tracing API, exposes this as RAY_FLAG_ACCEPT_FIRST_HIT_AND_END_SEARCH.

In words: find where the ray's line and the segment's line cross, then check that the crossing is ahead of the ray and between the segment's two ends. The 3D triangle version does the same with two edges.

ray–segment (2D): o + t·d = a + u·(b − a), e = b − a den = d × e (2D cross) t = ((a − o) × e) / den, u = ((a − o) × d) / den hit ⇔ den ≠ 0, t > 0, 0 ≤ u ≤ 1 Möller–Trumbore (3D triangle v0 v1 v2): E1 = v1 − v0, E2 = v2 − v0, P = d × E2, det = E1 · P T = o − v0, u = (T · P) / det, Q = T × E1 v = (d · Q) / det, t = (E2 · Q) / det hit ⇔ u ≥ 0, v ≥ 0, u + v ≤ 1, t > 0

o and d are the ray, a and b the segment's ends, t the distance along the ray and u the position along the segment, 0 at a and 1 at b. In Möller–Trumbore, v0 v1 v2 are the triangle corners, E1 and E2 two of its edges, and u and v say where inside the triangle the hit landed.

What this code does: pops boxes off a 32-deep stack, skips the ones the ray misses, tests segments in leaves, and pushes the far child before the near one so the near one comes off first.

uint stack[32]; int sp = 0; stack[sp++] = ROOT;
float tMax = ray.tMax; int hit = NONE;
while (sp > 0) {
  Node n = nodes[stack[--sp]];
  float tNear;
  if (!slab(n.bmin, n.bmax, o, invD, tMax, tNear)) continue;  // also culls boxes past the current hit
  if (n.isLeaf) {
    for (uint i = n.first; i < n.first + n.count; i++) {
      float t = intersect(prims[i], o, d);
      if (t > 0.0 && t < tMax) { tMax = t; hit = i; if (ANY_HIT) return hit; }
    }
  } else {
    bool leftFirst = d[n.axis] >= 0.0;         // near child = the side the ray comes from
    stack[sp++] = leftFirst ? n.right : n.left;   // far, popped last
    stack[sp++] = leftFirst ? n.left  : n.right;  // near, popped next
  }
}

Moving props without rebuilding everything

Boulders, oaks and crates dropped around the village. Drag one and only a tiny top tree is rebuilt; switch on the wind and the bending oaks' own tree has to be regrown every frame.

Wind

Moving a prop is a cheap top-tree rebuild; changing a prop's shape means regrowing its own tree, and regrown trees go stale.

Under the hood: the math and the code

A bottom-level acceleration structure (BLAS) is the BVH built once per mesh, in the mesh's own coordinate space. The top-level acceleration structure (TLAS) is a small BVH over the instances' world-space boxes, and each of its leaves holds a transform and a pointer to a BLAS. A ray that reaches an instance leaf is transformed into that mesh's space and continues down the BLAS there. The direction is not renormalized, so t keeps meaning the same distance in both spaces and the closest hit across instances is a plain comparison.

This is why moving objects is cheap and deforming them is not. A moved instance changes one TLAS leaf and the TLAS is rebuilt from scratch, a few hundred nodes at most. A skinned or deforming mesh changes vertex positions, so its BLAS is refit: every box is recomputed from the bottom up, but the tree shape is kept. Refit is fast, and the tree gets worse as vertices drift from where it was built, so engines rebuild those BLASes every few frames.

In words: push the ray through the inverse of the instance's transform and t comes out the same on both sides. Refit walks the tree from the leaves up, regrowing each box around whatever is under it.

instance transform M = T · R · S o' = M⁻¹ · o, d' = M⁻¹ · d (linear part only, do not normalize d') o' + t·d' = M⁻¹ · (o + t·d) so t is identical in object and world space refit: for node in reverse build order leaf: box = union of its primitives interior: box = union of both child boxes

M is the instance transform, built from a translation T, a rotation R and a scale S. o' and d' are the ray's start and direction once moved into the mesh's own space.

What this code does: the DXR shader set for one frame. RayGen fires a ray per pixel, ClosestHit shades the nearest surface, AlphaTest lets rays pass through the cut-out parts of a texture, and Miss paints the sky.

RaytracingAccelerationStructure Scene : register(t0);   // the TLAS
struct Payload { float3 color; float t; };

[shader("raygeneration")]
void RayGen() {
  uint2 px = DispatchRaysIndex().xy;
  RayDesc ray = CameraRay(px, DispatchRaysDimensions().xy);   // Origin, Direction, TMin, TMax
  Payload p; p.color = 0; p.t = -1;
  // hit group = instance offset + geometryIndex * stride + rayContribution; that is the shader table
  TraceRay(Scene, RAY_FLAG_NONE, 0xFF, /*rayContribution*/0, /*stride*/1, /*missIndex*/0, ray, p);
  Output[px] = float4(p.color, 1);
}
[shader("closesthit")]
void ClosestHit(inout Payload p, BuiltInTriangleIntersectionAttributes a) {
  p.t = RayTCurrent();                          // world t, same value the BLAS found in object space
  p.color = Shade(InstanceID(), PrimitiveIndex(), a.barycentrics);
}
[shader("anyhit")]
void AlphaTest(inout Payload p, BuiltInTriangleIntersectionAttributes a) {
  if (SampleAlpha(PrimitiveIndex(), a.barycentrics) < 0.5) IgnoreHit();   // keep traversing
}
[shader("miss")]
void Miss(inout Payload p) { p.color = Sky(WorldRayDirection()); }

Under the hood: the math and the code

At 1920×1080 one ray per pixel is 2,073,600 rays. A frame at 60 Hz is 16.7 ms, so every ray per pixel you add costs rays / rate of that budget. The quoted hardware rate is a peak for coherent rays, meaning rays that follow near-identical paths through the tree. Incoherent rays run well below it, and denoising, hit shading and the BVH update come on top.

Coherence is the whole reason. Neighbouring primary rays, the ones fired from the camera, walk the same nodes and land in the same few leaves, so their box tests hit cache and their GPU lanes stay together. Diffuse bounce rays leave one point in every direction and scatter across the tree. Same number of rays, several times the memory traffic.

In words: rays per frame is pixels times rays per pixel, and milliseconds is rays divided by the hardware rate.

rays_per_frame = W · H · (shadow + reflection + gi rays per pixel) ms_per_frame = rays_per_frame / rate rate in rays per second 1080p, 1 ray/px, 10 Grays/s → 2,073,600 / 1e10 = 0.21 ms (peak, coherent; estimate)

W and H are the target width and height in pixels, rate is rays per second, and 10 Grays/s is ten billion rays per second.

What this code does: fires one shadow ray per pixel toward the light, tells the hardware to stop at the first hit and skip shading, and turns the result into a 0 or 1 visibility.

// one shadow ray per pixel: any hit ends the search and no closest-hit shader runs
RayDesc r; r.Origin = P + N * 0.01; r.Direction = L; r.TMin = 0; r.TMax = distToLight;
ShadowPayload sp; sp.occluded = true;          // the miss shader sets it false
TraceRay(Scene,
  RAY_FLAG_ACCEPT_FIRST_HIT_AND_END_SEARCH | RAY_FLAG_SKIP_CLOSEST_HIT_SHADER,
  0xFF, 0, 1, /*shadow miss*/1, r, sp);
visibility = sp.occluded ? 0.0 : 1.0;           // then a temporal denoiser, because 1 ray is noisy

In a game, "ray traced" almost never means path traced: it means one or two rays per pixel per effect, then a denoiser and an upscaler, so the result is a filtered estimate rather than a converged image. The other surprise is where the time goes. Tracing two million shadow rays is often cheaper than refitting the trees of every animated character that frame, so the BVH update is frequently the real cost of turning ray tracing on.
