Temporal Upscaling

Temporal upscaling draws a smaller picture each frame and builds the full-size one from that frame plus the last few. You skip shading every pixel you did not draw, and pay a fixed 1 to 2 ms for the upscaler at 4K. The missing pixels are not guessed from their neighbours. They were drawn on earlier frames at slightly shifted positions and moved into place, which is why DLSS 2, FSR 2, XeSS and Unreal's TSR all need depth, motion vectors and the jitter offset from the engine, while a one-frame upscaler such as FSR 1 needs none of that and can only sharpen what it has.

Shift the grid a little each frame

Watch the coarse input grid slide under the fine output grid, and hover an output pixel to count the samples it has collected.

hover an output pixel

The GPU draws a coarse grid of samples, spaced wider than the screen pixels. Every frame the whole grid slides by a fraction of a pixel, so the samples land in new spots. After a few frames every screen pixel has been hit several times, and there is enough real detail to build a sharp full-size picture. Some cameras do the same thing: nudge the sensor between shots, then stack the shots.

Scale

The real version

Scale s is output resolution over input resolution. At 2× one input pixel covers 2 by 2 output pixels, so a single frame gives each output pixel a quarter of a sample on average. Sixteen frames give four. The counter in each cell is that coverage, computed from the offsets in use.

The offsets come from a Halton sequence, a fixed list of points that spreads evenly over a square without forming a repeating pattern, base 2 for x and base 3 for y. FSR 2 sizes the sequence at 8·s² phases, 32 at 2×, so each output sub-cell sees several distinct offsets before the pattern repeats.

The offset goes into the projection matrix, the maths that maps 3D points onto the screen, not into the camera's position. The whole scene shifts by less than one input pixel, depth and motion vectors stay consistent, and the upscaler subtracts the same offset when it places the samples.

In words: the shift for frame k is the next point in the Halton sequence, centred on zero; after N frames each output pixel has about N/s² samples.

s = r_out / r_in 1.5, 2 or 3 j_k = (Halton₂(k) − 0.5, Halton₃(k) − 0.5) in input pixels, k = 1..phases samples per output pixel after N frames ≈ N / s² = N·(r_in / r_out)² phases = 8·s² 32 at 2×, 72 at 3×

s is the scale, r_out and r_in the output and input resolutions, j_k the jitter for frame k in input pixels, and N the number of frames accumulated so far.

What this code does: picks this frame's offset from the sequence, nudges the projection matrix by that much, and hands the same offset to the upscaler so it can undo it.

// once per frame, before building the view-projection matrix
int  phase  = frameIndex % phaseCount;                // phaseCount = 8 * s * s
vec2 jitter = vec2(halton(phase + 1, 2), halton(phase + 1, 3)) - 0.5;
mat4 proj   = perspective(fovY, aspect, zNear, zFar);
// one input pixel is 2/renderWidth wide in NDC; the sign follows your convention
proj[2][0] += 2.0 * jitter.x / renderWidth;
proj[2][1] -= 2.0 * jitter.y / renderHeight;
viewProj = proj * view;
// hand the same offset to the upscaler, in pixels, so it can undo it
upscaler.jitterPixels = jitter;

Jitter turns a stream of coarse frames into a full set of real samples; the upscaler only has to know the offsets.

Reuse last frame, or throw it away

A box slides over a still background; each output pixel looks back along its motion arrow for its own history, and drops it when that history belongs to something else.

40×20 output · 20×10 input · 2×

To reuse last frame, each pixel has to know where it was last frame. A motion vector, how far the pixel moved since then, points the way. But when something moves it uncovers background that was hidden, and that background has no history of its own, only the box's. So each pixel compares depths, and if the old pixel sat at a different distance from the camera, it throws the history away and starts fresh.

The real version

The white arrows are motion vectors: the box's pixels read history one step back, which is where the box was. The background has zero motion, so the pixels the box just left read history at their own position, and that history holds the box's colour and its depth.

That depth does not match the background depth rendered this frame, so the history is rejected and those pixels start over from the current frame's samples. This is disocclusion handling: a disocclusion is a spot that was hidden last frame and is visible now.

Turn rejection off and the same pixels blend stale box colour into the background: a ghost trail that fades over about ten frames. The cheaper test is a neighbourhood clamp, which clips the history colour to the min and max of the 3 by 3 current samples around it. It needs no depth, but it also erases thin features the current frame missed, which the failures section shows.

In words: step back along the motion vector, read the old depth there, and if it disagrees with this frame's depth, use only this frame's samples.

uv_prev = uv − mv(uv) mv in output pixels z_reproj = z_hist(uv_prev) reject if |z_reproj − z_cur| > ε ε = 0.05 of the depth range here or clamp: c_hist = clamp(c_hist, min₃ₓ₃(c_in), max₃ₓ₃(c_in)) c = lerp(c_hist, c_in, α) α = 1 when rejected

uv is the pixel's position, mv its motion vector, z_hist and z_cur the old and new depths, ε the tolerance, c_hist and c_in the old and new colours, and α the share of new colour in the blend.

What this code does: finds where the pixel was last frame, checks that spot is still on screen, compares the two depths in real distance units, and sets the history count to zero when they disagree.

// disocclusion test, one output pixel; ip = nearest input pixel
vec2  mv       = texelFetch(motionTex, ip, 0).xy;         // output pixels, this frame → last
vec2  uvPrev   = uv - mv * invOutputSize;
bool  onScreen = all(greaterThanEqual(uvPrev, vec2(0.0))) && all(lessThan(uvPrev, vec2(1.0)));
float zHist    = textureLod(historyDepth, uvPrev, 0.0).x;
float zNow     = texelFetch(depthTex, ip, 0).x;
// compare linear depth; a fixed NDC epsilon fails at distance
bool  disoccluded = abs(linearize(zHist) - linearize(zNow)) > 0.01 * zFar;
float historyLen  = (onScreen && !disoccluded) ? textureLod(historyLen, uvPrev, 0.0).x : 0.0;
// historyLen 0 means: use only this frame's samples and start accumulating again

Motion vectors say where a pixel came from; the depth test says whether that history is still the same surface.

Add the frames up, then sharpen

The same still scene three ways, with the error against a high-quality reference measured live.

RMSE in 0–255 units, lower is better

Each output pixel keeps a running average of every sample that has landed near it, plus a count of how much it has seen. New samples count more when they land close to the pixel centre. The count is capped at 32, so old samples keep fading and the picture can still change. The result is a touch soft, so a sharpen pass runs at the end.

The real version

The blend is a running average weighted by confidence. Each output pixel keeps a colour and a count n of how much sample weight it has absorbed. This frame's samples arrive with weight w, a Gaussian (a bell curve) of the distance from the output pixel centre to the jittered input sample, half an output pixel wide.

The kernel, the weighting shape used to gather samples, is sized for the output grid, not the input grid. The jitter is what makes that legal: over several frames, samples land close to every output pixel centre. The count is capped, 32 here, so old samples keep fading and the image stays responsive.

After a camera cut the count is zero everywhere and the first frame is exactly the bilinear result. The graph shows the RMSE falling as samples accumulate, and a floor it never crosses: the converged image is the scene blurred by the kernel, a touch softer than the box-filtered reference.

That floor is what the sharpen pass is for. RCAS is a 3 by 3 cross-shaped kernel that subtracts a little of the four neighbours. The amount is limited by the local min and max, so it sharpens edges without adding bright or dark halos on them.

In words: weight each new sample by how close it landed, fold it into the running average, and raise the count. RCAS then pushes each pixel away from the average of its four neighbours, within a limit.

w_i = exp(−2·d_i²) d_i = |p_out − p_sample| in output pixels, σ = 0.5 px c = (n·c_hist + Σ w_i·c_i) / (n + Σ w_i) n' = min(n + Σ w_i, n_max) n_max = 32 α = Σ w_i / (n + Σ w_i) the same blend as lerp(c_hist, c_in, α) RCAS: c' = (e + lobe·(b+d+f+h)) / (1 + 4·lobe), lobe ∈ [−0.1875, 0]

w_i is the weight of sample i, d_i its distance from the pixel centre, n the accumulated count, c_hist the old colour, c_i the new sample colours, n_max the cap, and α the equivalent blend factor. In the RCAS line e is the centre pixel and b, d, f, h its four neighbours.

What this code does: finds the 3 by 3 input samples around the pixel, weights each by distance, reads the history at the reprojected spot, clamps or rejects it, then averages history and new samples by their weights.

// resolve kernel for output pixel p (output px); j = this frame's jitter (input px)
vec2  q = p / s - 0.5 - j;                     // position in input sample space
ivec2 c = ivec2(round(q));
vec3 sum = vec3(0); float wsum = 0.0; vec3 boxMin = vec3(1e9), boxMax = vec3(-1e9);
for (int dy = -1; dy <= 1; dy++) for (int dx = -1; dx <= 1; dx++) {
  ivec2 t  = c + ivec2(dx, dy);
  vec3  ci = texelFetch(inputColor, t, 0).rgb;
  vec2  dp = (q - vec2(t)) * s;                  // offset to that sample, output px
  float w  = exp(-2.0 * dot(dp, dp));            // jitter-aware weight, sigma 0.5 px
  sum += w * ci; wsum += w; boxMin = min(boxMin, ci); boxMax = max(boxMax, ci);
}
vec4 h = sampleCatmullRom(history, uvPrev);     // rgb + accumulated weight n; bicubic, not bilinear, or the history blurs
h.rgb = clamp(h.rgb, boxMin, boxMax);           // or the depth test from section 2
float n = disoccluded ? 0.0 : h.a;
vec3 outColor = (n * h.rgb + sum) / max(n + wsum, 1e-4);
historyOut = vec4(outColor, min(n + wsum, N_MAX));

The output is a running average of jittered samples, capped so it can still change, then sharpened to make up for the blur.

Where it breaks

A camera pans over thin posts, a striped floor, a drifting glow and a HUD; each toggle fixes one artifact, and all four start off.

160×90 output · 80×45 input · 2×

The upscaler only knows what the engine tells it, so every artifact is a missing input. Thin things fall between samples and flicker. A glow that writes no motion vector smears along its path. A HUD drawn before the upscale comes out soft. Textures come out blurry because the GPU picked a smaller copy to suit the smaller frame. Each one has a one-line fix on the engine side.

The white bars and crosshair are the HUD.

The real version

The posts are half an output pixel wide. On many frames no input sample lands on one, so the current frame says background there while the history says post, the depth test rejects, and the post flickers. Engines keep wires and railings at least one input pixel wide, or draw them after the upscaler.

The particle is translucent, so it writes neither depth nor motion vectors. Its pixels carry the background's motion, the history is fetched from the wrong place, and the particle smears along its own path. FSR 2 takes a reactive mask, a per-pixel flag, for exactly these pixels; Unreal has a "responsive AA" material flag that does the same job.

The HUD is static on screen, so it accumulates cleanly, but it was rendered at input resolution and rebuilt through the kernel, so its edges are soft. Anything drawn in screen space belongs after the upscaler.

The stripe texture is soft because the GPU picks mip levels from how fast the texture coordinates change per input pixel, which at 2× is one level coarser than at native. A negative LOD bias on every material sampler, a fixed nudge toward the sharper mip, puts it back.

In words: the smaller frame makes the GPU pick a blurrier texture copy; biasing by log2 of the scale picks the copy that native rendering would have used.

mip = log2(texels per input pixel) = mip_native + log2(s) bias = log2(r_in / r_out) = −log2(s) −0.58 at 1.5×, −1 at 2×, −1.58 at 3× footprint after bias = 2^(mip + bias) texels = the native footprint

mip is the texture level the GPU picks, s the scale, r_in and r_out the two resolutions, and the footprint is how many texels one pixel covers.

What this code does: shifts every texture lookup toward the sharper mip by the scale, flags translucent particles for the upscaler, and leaves screen-space overlays for after it.

// material shader, internal-resolution pass
float mipBias = log2(renderWidth / outputWidth);          // -1.0 at 2×; or set it on the sampler
vec4  albedo  = texture(albedoTex, uv, mipBias);
// translucent particles: no depth, no motion vectors, so flag them for the resolve
if (material.responsive) reactiveMask = max(reactiveMask, albedo.a);
// HUD, film grain, vignette, letterbox: draw at output resolution, after the upscaler

Ghost trails, flicker, blur and soft HUDs are all inputs the engine forgot to hand the upscaler.

What it costs

Pick an output size and a mode, and see an estimated frame time split into the part that shrinks and the parts that do not.

estimates, not measurements

The upscaler costs a fixed slice of GPU time, about 1 to 2 ms at 4K, and in return you skip shading most of the pixels. But only the part of the frame that scales with pixel count gets cheaper. Shadow maps, culling, simulation and the HUD cost the same at any input size, so the saving depends on how much of your frame was pixel work to begin with.

The real version

The mode names are the DLSS and FSR 2 presets: Quality renders at 1/1.5 of the output on each axis, Balanced at about 1/1.7, Performance at 1/2, Ultra Performance at 1/3. 4K Performance shades 1920×1080 pixels, a quarter of the output. 4K Quality shades 2560×1440, 44 %.

Shadow maps, culling, simulation and the HUD do not get cheaper, so the saving is the resolution-dependent share divided by s², minus the upscaler itself. Published figures put a temporal upscaler at roughly 1 to 2 ms at 4K output on 2022-era GPUs; the slider is that number, scaled by output pixel count for the smaller targets. The bars are the model, not a benchmark.

Dynamic resolution takes this one step further: the engine measures last frame's GPU time and picks the scale for the next frame so the total lands on budget.

In words: frame time is the fixed part, plus the pixel part divided by s², plus the upscaler; the upscaler's cost follows the output size, not the input size.

t_frame ≈ t_fixed + t_scaled / s² + t_upscale pixels shaded = (w_out / s) · (h_out / s) 3840×2160 at 2× → 2.07 M t_upscale ∝ output pixels, not input pixels

t_frame is the whole frame, t_fixed the part that ignores resolution, t_scaled the part that follows pixel count, t_upscale the upscaler, s the scale, and w_out and h_out the output width and height.

What this code does: reads how long the last frame took, nudges the scale a little toward the budget, and rounds the new input size to even numbers.

// dynamic resolution: choose s each frame so GPU time lands on budget
float gpuMs = readTimestampQuery(previousFrame);
float ratio = clamp(budgetMs / gpuMs, 0.85, 1.15);          // damp it; never chase one spike
scale = clamp(scale * sqrt(ratio), 1.0 / 3.0, 1.0);           // area scales with scale², hence sqrt
renderWidth  = roundToEven(outputWidth  * scale);
renderHeight = roundToEven(outputHeight * scale);
// the upscaler must accept a varying input size; jitter length and mip bias follow scale

Temporal upscaling only shrinks the pixel-bound part of the frame, so measure that share before you count on a saving.

Tradeoffs

Four families that all end at a full-size picture. What each one needs from the engine is the real difference; quality follows from that.

Read the rows top to bottom as rising effort and rising payoff. A spatial upscaler is a day of work and gives a soft picture. A temporal one is weeks of engine plumbing and gives back real detail. The ML versions swap the hand-tuned rules for a trained network on the same inputs. Frame generation sits on top of a temporal upscaler and invents whole frames. The trap: the upscaler only sees what was rendered. It cannot know that a texture scrolls, an animated character bends, a portal shows another room, or a particle drifts, unless the engine writes a correct motion vector for every one of those pixels, animated UVs included. Nearly every ghosting or smearing report traces back to a missing or wrong motion vector, not to the upscaler.
