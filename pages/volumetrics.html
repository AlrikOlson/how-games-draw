Volumetric Fog

Fog in a game is light bouncing off tiny specks in the air, and the engine has to work out how much of that light reaches each pixel of the screen. Done well it gives light shafts between trees, glowing lamp cones and dark air behind a trunk, for about 1 to 2 ms of each frame. The thing people get wrong: fog is not a colour you tint the screen with. Fog has no colour of its own. What you see is light from the scene's lamps, so it is bright inside a floodlight's cone and dark behind a tree.

One line of sight through the fog

A player on a rise at the edge of a foggy forest at night, and a floodlight on a mast shining down through the trees. Pick one line of sight and watch the glow along it get added up step by step.

—

Fog glow is lit fog added up along the line of sight, with each step counting for less than the one before it.

Under the hood: the math and the code

Each step reads the fog density ρ, the amount of material per metre. The extinction coefficient σ_t is how fast that material dims light, and the scattering coefficient σ_s is the part that redirects light rather than absorbing it. Their ratio is the albedo, 0.9 here, meaning 90% of what the fog stops gets bounced rather than eaten.

The phase function p(θ) says how much of that bounce heads back to the player, for the angle θ between the light and the view ray. V is the shadow test: 1 if the floodlight can see the point, 0 if a tree is in the way. Transmittance T is the running product of every step's dimming so far, so glow found far along the ray counts for less.

In words: at each point along the ray, take the fog there, times the light reaching it, times how much bounces your way, times how much of that survives the trip back to the eye. Add it all up.

T(t) = exp( −∫₀ᵗ σ_t(s) ds ) transmittance, 1 → 0 L = ∫₀ᴰ T(t) · σ_s(t) · p(θ) · L_light(t) · V(t) dt single scattering σ_s = albedo · σ_t here albedo = 0.9, σ_t in 1/m pixel = L_surface · T(D) + L

T(t) is transmittance at distance t, σ_t the extinction per metre, σ_s the scattering part of it, p(θ) the phase function, L_light the floodlight's brightness at that point, V the shadow test, D the distance to whatever the ray hits, and L_surface the colour of that surface.

What this code does: walks the ray in STEPS equal steps, and at each one adds lit fog scaled by the transmittance so far, then shrinks the transmittance.

// one view ray, STEPS samples; each step checks the light's shadow map
vec3 T = vec3(1.0), L = vec3(0.0);
float dt = rayLength / STEPS;
for (int i = 0; i < STEPS; i++) {
  vec3  p    = ro + rd * (float(i) + 0.5) * dt;
  float rho  = density(p);                  // base fog + fog that thins with height + local blobs
  float sigT = rho, sigS = albedo * rho;
  float V    = shadowMap(p);                // 1 lit, 0 shadowed
  vec3  Li   = lightColor * spotFalloff(p) * V;
  float ph   = hg(dot(-rd, normalize(p - lightPos)), g);
  vec3  stepT = exp(-sigT * dt);
  L += T * sigS * ph * Li * (1.0 - stepT) / sigT;   // exact across the whole step, more accurate than sigS*dt
  T *= stepT;
}
color = sceneColor * T + L;

Under the hood: the math and the code

The phase function p(θ) is to a particle what a BRDF is to a surface: the rule for how much light arriving from one direction leaves toward another. θ is the angle between the light's direction of travel and the direction to your eye. It integrates to 1 over the sphere, so it only redistributes light and never adds any.

The one knob, g, is called anisotropy and is the average of cosθ. At g = 0.9 a peaky lobe sends 15 sr⁻¹ straight ahead and almost nothing backward, while g = 0 sends 1/4π = 0.08 sr⁻¹ everywhere. Engines usually use a single Henyey-Greenstein lobe with g around 0.3 to 0.7, or mix a forward lobe with a small backward lobe.

In words: the closer the outgoing direction is to the light's own direction of travel, the more light goes that way, and g sets how sharp that preference is.

p(θ) = (1 − g²) / ( 4π (1 + g² − 2g cosθ)^1.5 ) cosθ = ω_light · ω_out ∫ p dω = 1 over the sphere; g = ⟨cosθ⟩, −1 (back) … 0 (isotropic) … 1 (forward)

g is the anisotropy from −1 to 1, θ the angle between the light direction ω_light and the outgoing direction ω_out, and the 4π is what makes the whole sphere add up to 1. The rings on the plot mark 10⁻³ up to 10 per steradian, a steradian being a unit of solid angle, the 3D version of an angle.

What this code does: computes one Henyey-Greenstein lobe, then blends in a small backward lobe for the two-lobe version most engines ship.

float hg(float cosTheta, float g) {
  float g2 = g * g;
  float d  = 1.0 + g2 - 2.0 * g * cosTheta;
  return (1.0 - g2) / (4.0 * PI * d * sqrt(d));   // d^1.5 without calling pow()
}
// cosTheta: light propagation direction dotted with the direction toward the eye
float phase(vec3 rd, vec3 toLight) {
  float c = dot(-rd, -toLight);              // == dot(rd, toLight)
  return mix(hg(c, 0.7), hg(c, -0.2), 0.15); // two lobes: a small amount scatters backward
}

Under the hood: the math, the code and real grid sizes

The frustum is the wedge of space the camera can see, and a froxel is one cell of it, short for frustum voxel. Unreal's default at 1080p is one froxel per 8×8 pixel tile and 64 depth slices: 2,073,600 froxels, the same count as pixels, but each one is written once and read by the 64 pixels along its column.

Depth slices are spaced logarithmically, close together near the camera and further apart far away, so a cell covers about the same number of screen pixels near and far. The injection pass stores two things per cell: scattering, the lit glow, and extinction, how much the cell dims light. The integration pass walks each column front to back carrying transmittance, and writes the built-up glow and transmittance back into each cell.

Applying fog to a pixel is then one 3D texture read at its depth. Surfaces never stop the integration; the depth buffer, the per-pixel record of how far away each surface is, just picks which slice to read.

Cells are coarse, so shadow edges and light cones come out blocky. Two fixes ship together. Trilinear filtering blends the eight cells around a sample point instead of snapping to one. Jittering moves the sample point inside each cell every frame and blends with last frame's result, shifted to line up with the camera's motion. With the camera still, as here, that shift is nothing and the history is a plain running average.

In words: fill every cell with lit fog, sweep each column from front to back adding up glow and multiplying down transmittance, then read one cell per pixel.

z_i = n · (f/n)^(i/N) log slices, n = 0.5 m, f = 16 m inject: S_i = σ_s ρ p(θ) L_light V E_i = σ_t ρ per cell integrate: L += T · S_i · (1 − e^(−E_i Δz)) / E_i ; T *= e^(−E_i Δz) apply: pixel = colour · T(z) + L(z) one trilinear read

z_i is the front of slice i out of N, n and f the near and far distances, S_i and E_i the scattering and extinction stored in a cell, Δz the slice thickness, and T(z) and L(z) the values read at a pixel's depth.

What this code does: one thread per column sweeps front to back, storing the running glow and transmittance in every cell; then each pixel does one filtered texture read to apply it.

// integration pass: one thread per froxel column, scanning front to back
vec3 L = vec3(0.0); float T = 1.0;
for (int z = 0; z < SLICES; z++) {
  vec4  cell   = injected[ivec3(xy, z)];       // rgb = lit glow (σ_s ρ p Li V), a = extinction (σ_t ρ)
  float dz     = sliceDepth(z + 1) - sliceDepth(z);
  float stepT  = exp(-cell.a * dz);
  L += T * cell.rgb * (1.0 - stepT) / max(cell.a, 1e-5);
  T *= stepT;
  integrated[ivec3(xy, z)] = vec4(L, T);
}
// apply, in the lighting or composite pass: one trilinear fetch per pixel
vec3 uvw  = vec3(screenUV, sliceFromDepth(viewZ));  // log mapping, same as injection
vec4 fog  = texture(integratedVolume, uvw);
color = color * fog.a + fog.rgb;

Ground mist is one formula per pixel: nearly free, but it can only ever be one flat colour.

Under the hood: the math and the code

Optical depth τ is how much fog a ray has passed through, added up, and transmittance is exp(−τ). When density depends only on height, ρ(h) = d0 · exp(−h/H), where d0 is the density at the ground and H is the scale height, the knob for how fast the fog thins as you climb. For that profile the integral along a straight ray collapses to one exponential and a division.

The march needs N density taps to approach the same number, and at low N it is visibly wrong wherever the ray crosses the steep part of the profile near the ground.

The price is that the light term is a constant colour, usually the sun or sky. There is no shadowing and no light shafts, because the formula only knows about density, not about where the lights are. Distance fog is the same formula with H set to infinity, so density is uniform and optical depth is simply d0 · D.

In words: the fog a ray crosses equals the density at your eye, times a factor for how fast the ray climbs or dives, times how far it goes before it hits something.

ρ(h) = d0 · exp(−h / H) τ = ∫₀ᴰ ρ(h₀ + t·dir_y) dt = d0 · exp(−h₀/H) · (H / dir_y) · (1 − exp(−dir_y · D / H)) (dir_y = 0: τ = d0 · exp(−h₀/H) · D; H → ∞: τ = d0 · D, plain distance fog) T = exp(−τ); pixel = colour · T + fogColour · (1 − T)

h₀ is the player's eye height, dir_y the vertical part of the ray direction, D the distance to the surface, τ the optical depth and T the transmittance.

What this code does: computes the exact optical depth from the camera height and ray slope, with a special case for level rays, then blends the pixel toward one fog colour.

// exact exponential height fog, per pixel, no loop
float heightFogOpticalDepth(vec3 ro, vec3 rd, float D) {
  float k = rd.y / H;
  float base = d0 * exp(-ro.y / H);
  if (abs(k) < 1e-4) return base * D;      // level ray: no change in height
  return base * (1.0 - exp(-k * D)) / k;
}
float T = exp(-heightFogOpticalDepth(cameraPos, rd, sceneDepth));
color = mix(fogColor, color, T);              // fogColor is one constant, see the note at the end of the page

Clouds cost the steps along the line times one plus the steps toward the sun, which is why they are drawn small and spread over many frames.

Under the hood: the math and the code

Density comes from a noise field, a texture of random-looking bumps at several scales, so every sample costs several texture reads. The sun term at each sample is another march of M steps, so a pixel costs N · (1 + M) samples. The tiles multiply that by the pixels in a 1080p frame and by a chosen cost per sample, which is why shipped clouds render at reduced resolution and update a fraction of the pixels each frame.

Beer-Lambert is the plain rule: light through material falls off as exp(−τ). It makes cloud edges brightest, since they have the least material between them and the sun. Real clouds show dark edges and a bright interior, because thin regions scatter light out of the view before it can bounce back. The "powder" term 1 − exp(−2τ) fakes that with no extra samples.

In words: for each step on the view ray, march a few steps toward the sun to see how much cloud blocks it, then add the lit cloud and dim the ray.

Beer-Lambert: E(τ) = exp(−τ), τ = ∫ σ_t ds toward the sun (M samples) Beer-Powder: E(τ) = 2 · exp(−τ) · (1 − exp(−2τ)) samples per pixel = N · (1 + M); ms ≈ pixels · samples · cost_per_sample

E(τ) is the sunlight reaching a sample after passing through optical depth τ, N the view steps, M the sun steps, and cost_per_sample the time for one density lookup.

What this code does: a loop inside a loop, N steps along the view with M short steps toward the sun at each, and an early exit once the ray can't see any further.

// nested march: N view samples, each with M samples toward the sun
float T = 1.0; vec3 L = vec3(0.0);
for (int i = 0; i < N; i++) {
  vec3 p = ro + rd * t;
  float rho = cloudDensity(p);              // shape noise × erosion noise × height profile
  if (rho > 0.0) {
    float tau = 0.0;
    for (int k = 0; k < M; k++)            // short march, coarser steps than the view ray
      tau += cloudDensity(p + sunDir * (float(k) + 0.5) * dsSun) * dsSun;
    float E = 2.0 * exp(-tau) * (1.0 - exp(-2.0 * tau));  // Beer-Powder
    L += T * rho * E * sunColor * hg(dot(rd, sunDir), 0.3) * dt;
    T *= exp(-rho * dt);
    if (T < 0.01) break;                 // stop early once the ray can't see any further
  }
  t += dt;
}

Fog colour is not a tint. What you see in fog is light from the scene's lamps, so it is bright inside a lamp's cone, dark behind a tree, warm near a lantern and blue under the sky. A baked fog colour stays the same when a light moves, which is why formula fog looks wrong the moment a headlight sweeps through it, while froxel fog and marching work the colour out from the lights so it moves with them.
